# Contributing to Vehicle Price Predictions

This outlines how to propose a change to Vehicle Price Predictions. 

### Fixing typos

Small typos or grammatical errors in documentation may be edited directly using
the GitHub web interface, so long as the changes are made in the _source_ file.

*  YES: you edit the Quarto source file `analysis/vehicle-price-prediction.qmd`
*  NO: you edit the rendered `analysis/vehicle-price-prediction.html` or `.pdf`.

### Prerequisites

Before you make a substantial pull request, you should always file an issue and
make sure someone from the team agrees that it's a problem. If you've found a
bug, create an associated issue and illustrate the bug with a minimal 
[reprex](https://www.tidyverse.org/help/#reprex).

### Setting up the project

Install [uv](https://docs.astral.sh/uv/getting-started/installation/) and
[Quarto](https://quarto.org/docs/get-started/), then clone the repository and
create the virtual environment from the root of the repository:

``` bash
git clone https://github.com/UBC-MDS-2026-27/DSCI-522-Vehicle-Price-Predictions.git  
cd DSCI-522-Vehicle-Price-Predictions
uv sync --locked
```

To re-run the analysis and render the report from the root directory:

``` bash
uv run quarto render analysis/vehicle-price-prediction.qmd
```

If your change needs a new Python package, add it with `uv add <package>`. This records the dependency requirement in `pyproject.toml` and updates the resolved package versions in `uv.lock`. Commit both files.

### Pull request process

*  Create a new Git branch for each pull request (PR), starting from an
   up-to-date `main`. Do not commit directly to `main`.
*  Give the branch a short name that describes the work,
   for example `fix-readme-typo` or `add-eda-figure`.
*  Keep each branch small: one independent piece of work per branch.
*  Before opening the PR, render the report (`uv run quarto render analysis/vehicle-price-prediction.qmd`)
   to check that the analysis still runs from start to finish.
*  Open a PR into `main` and describe what changed and why.
   Link the related issue (e.g., "Closes #12").
*  At least one other team member must review and approve the PR before it is merged.
   The reviewer, not the author, merges it.
*  New code should follow the PEP8 [style guide](https://peps.python.org/pep-0008/).

### Code of Conduct

Please note that this project is released with a [Contributor Code of
Conduct](CODE_OF_CONDUCT.md). By participating in this project you agree to
abide by its terms.

### AI Policy
"AI" herein refers to generative AI tools like large language models (LLMs) that can generate, edit, and review software code, create and manipulate images, or generate human-like communication. 

#### Responsibility
You are responsible for any code you submit the Vehicle Price Predictions repositories, regardless of whether it was manually written or generated by AI. You must understand and be able to explain the code you submit as well as the existing related code. It is not acceptable to submit a patch that you cannot understand and explain yourself. In explaining your contribution, do not use AI to automatically generate descriptions. 

#### Disclosure
You must disclose whether AI has been used to assist in the development of your pull request. If so, you must document which tool(s) have been used, how they were used, and specify what code or text is AI generated. We will reject any pull request that does not include the disclosure. 

#### Code Quality
Code generated by AI can be of low quality. Contributors are expected to submit code of high quality. We will reject pull requests that we consider  low-quality or insufficiently reviewed. Do not waste developers' time by submitting code that is fully or mostly generated by AI, and does not meet our standards. 


#### Copyright 
Copyright is outlined in [`LICENSE.md`](LICENSE.md). Code generated by AI may infringe on copyright and it is the submitter's responsibility to not infringe. We reserve the right to reject any pull requests, AI generated or not, where copyright is in question. 

#### Communication
When interacting with developers in any capacity, do not use AI to speak for you, except for translation or grammar editing. 

#### AI Agents
The use of an AI agent that writes code and then submits a pull request autonomously is not permitted. A human must check any generated code and submit a pull request according to the 'Responsibility' section above.
